# 고급 스케줄러

**시스템에서 작업을 실행하는 평균 응답 시간을 줄이기 위해 [4.4BSD 스케줄러](advanced_scheduler.md#44bsd-scheduler)과 유사한 다단계 피드백 큐 스케줄러를 구현하십시오.**

우선순위 스케줄러와 마찬가지로 고급 스케줄러는 우선순위에 따라 실행할 스레드를 선택합니다. 그러나 선진 스케줄러는 우선적인 기부를 하지 않습니다. 따라서, 우리는 고급 스케줄러에 대한 작업을 시작하기 전에 우선순위 기부를 제외하고 우선 스케줄러가 작동하는 것을 권장합니다.

Pintos 시작 시 스케줄링 정책을 선택할 수 있도록 작성해야 합니다. 기본은 우선순위 스케줄러지만, `-mlfqs` 커널 옵션으로 4.4BSD 스케줄러를 선택할 수 있어야 합니다. `main()` 초기에 `parse_options()`가 옵션을 해석할 때 이 옵션이 있으면 `threads/thread.h`에 선언된 `thread_mlfqs`를 true로 설정합니다.

4.4BSD 스케줄러가 활성화되면 스레드가 더 이상 직접적으로 자신의 우선순위를 제어하지 않습니다. `thread_create()`에 대한 우선순위 인자과 `thread_set_priority()`에 대한 모든 호출이 무시되어야 하며, `thread_get_priority()`는 스케줄러에 의해 설정된 스레드의 현재 우선순위를 반환해야 합니다. 고급 스케줄러는 후속 프로젝트에서 사용되지 않습니다.

<a id="44bsd-scheduler"></a>

# 4.4BSD 스케줄러

일반목적 스케줄러의 목표는 스레드들의 다른 스케줄링 욕구를 균형을 맞추는 것입니다. 많은 I/O를 수행하는 스레드는 입력 및 출력 장치를 바쁘게 유지하기 위해 빠른 응답 시간이 필요하지만 CPU 시간이 거의 필요하지 않습니다. 다른 한편으로, 컴퓨팅 관련 스레드는 작업을 완료하기 위해 많은 CPU 시간을 받아야하지만 빠른 응답 시간을 요구하지 않습니다. 다른 스레드들은 중간에서 어딘가에 위치하고 있으며, I/O 기간은 계산 기간에 의해 단절되어 있으며, 따라서 시간이 지남에 따라 요구 사항이 달라집니다. 잘 설계된 스케줄러는 종종 이 모든 요구사항을 동시에 갖춘 스레드를 수용할 수 있습니다.

프로젝트 1에서는 이 부록에서 설명된 스케줄러를 구현해야 합니다. 우리의 스케줄러는 \[McKusick\]에서 설명된 것과 비슷합니다. 이것은 다단계 피드백 큐 스케줄러의 한 예입니다. 이 유형의 스케줄러는 실행할 준비가 된 스레드의 여러 줄을 유지하며, 각 줄은 다른 우선순위를 가진 스레드를 유지합니다. 주어진 시간에, 스케줄러는 가장 높은 우선순위가 있는 비 빈 줄을 중 하나의 스레드를 선택합니다. 가장 높은 우선순위 행렬이 여러 개의 스레드를 포함하면 "라운드 로빈" 순서로 실행됩니다.

스케줄러의 여러 측면은 특정 수의 타이머 틱 후에 데이터를 업데이트 할 필요가 있습니다. 모든 경우에, 이러한 업데이트는 일반적인 커널 스레드가 실행할 기회가 있기 전에 발생해야합니다. 따라서 커널 스레드가 새로 증가한 `timer_ticks()` 값을 볼 수 있지만 오래된 스케줄러 데이터 값을 볼 수있는 기회가 없습니다.

4.4BSD 스케줄러는 우선순위 기부를 포함하지 않습니다.

<a id="niceness"></a>

## nice 값

스레드 우선순위는 아래 식에 따라 스케줄러가 동적으로 결정합니다. 각 스레드에는 다른 스레드에 CPU를 얼마나 양보할지 나타내는 정수 nice 값도 있습니다. nice가 0이면 우선순위에 영향을 주지 않습니다. 최대 20까지의 양수 nice는 우선순위를 낮춰 원래 받을 CPU 시간의 일부를 양보하게 합니다. 반대로 최소 -20까지의 음수 nice는 다른 스레드의 CPU 시간을 더 가져오는 쪽으로 작용합니다.

최초 스레드의 nice 값은 0입니다. 그 뒤 생성하는 스레드는 부모의 nice 값을 상속합니다. 테스트 프로그램에서 사용할 다음 함수들을 구현해야 합니다. 함수의 기본 틀은 `threads/thread.c`에 있습니다.

```
int thread_get_nice (void);
```

> 현재 스레드의 nice 값을 반환합니다.

```
int thread_set_nice (int nice);
```

> 현재 스레드의 nice 값을 새 값으로 설정하고 이에 따라 우선순위를 다시 계산합니다. [우선순위를 계산](advanced_scheduler.md#calculating-priority)을 참고하세요. 실행 중인 스레드가 더 이상 최고 우선순위가 아니면 CPU를 양보합니다.

<a id="calculating-priority"></a>

## 우선순위 계산

이 스케줄러에는 0 `(PRI_MIN)`부터 `63 (PRI_MAX)`까지 64개 우선순위와 이에 대응하는 준비 큐 64개가 있습니다. 숫자가 작을수록 우선순위가 낮아 0이 최저, 63이 최고입니다. 스레드를 초기화할 때 처음 우선순위를 계산하고, 이후 모든 스레드에 대해 타이머 틱 4회마다 다시 계산합니다. 두 경우 모두 다음 식을 사용합니다.

> priority = PRI_MAX - (recent_cpu / 4) - (nice \* 2),

recent cpu는 스레드가 최근 사용한 CPU 시간의 추정치이고 nice는 해당 스레드의 nice 값입니다. 결과는 정수로 내림해 절삭합니다. recent cpu의 계수 1/4과 nice의 계수 2는 실용적으로 잘 동작하는 값이지만 더 깊은 의미가 있는 것은 아닙니다. 계산한 우선순위는 항상 `PRI_MIN`부터 `PRI_MAX`까지의 유효 범위로 조정합니다.

이 식은 최근 CPU를 사용한 스레드의 우선순위를 낮춰 다음 스케줄링에서 CPU를 다시 배정받기 어렵게 합니다. 이는 기아 방지의 핵심입니다. 최근 CPU 시간을 전혀 받지 못한 스레드의 recent cpu는 0이므로, nice 값이 높지 않다면 곧 CPU를 배정받을 수 있습니다.

<a id="calculating-recentcpu"></a>

## `recent_cpu` 계산

우리는 최근 CPU가 각각의 프로세스가 "최근"에 얼마나 많은 CPU 시간을 받았는지 측정하기를 원합니다. 또한, 정밀화로서, 최근 CPU 시간이 최근 CPU 시간보다 더 중화되어야합니다. 한 접근법은 마지막 n 초마다 수신된 CPU 시간을 추적하기 위해 n 요소의 배열을 사용합니다. 그러나 이 접근 방식은 새로운 중계 평균을 계산하기 위해 각 스레드마다 O (n) 공간과 O (n) 시간을 필요로 한다.

대신, 우리는 기하급수적으로 중화된 이동 평균을 사용합니다.

> x(0) = f(0),
>
> x(t) = ax(t − 1) + (1 − a)f(t),
>
> a = k/(k + 1),

`x(t)`가 정수 시간에 움직이는 평균인 경우 `t ≥ 0`, `f(t)`는 평균되는 함수이고 `k > 0`는 붕괴 속도를 조절한다. 우리는 다음과 같이 몇 단계에 걸쳐 수식을 반복할 수 있습니다.

> x(1) = f(1),
>
> x(2) = af(1) + f(2),
>
> ...
>
> x(5) = a^4 \* f(1) + a^3 \* f(2) + a^2 \* f(3) + a \* f(4) + f(5).

`f(t)`의 값은 `t`의 시간에 1의 무게, `a`의 시간에 `t + 1`의 무게, `a^2`의 시간에 `t + 2`의 무게 등이 있습니다. 우리는 또한 `x(t)`와 `k`: `f(t)`의 무게는 대략 `1/e`의 시간 `t + k`, 대략 `1/(e^2)`의 시간 `t + 2k`, 등과 관련이 있습니다. 반대 방향에서, `f(t)`는 시간 `t + log_a(w)`에서 무게로 `w`로 붕괴됩니다.

`recent_cpu`의 초기 값은 처음 생성된 스레드에서 0 또는 다른 새로운 스레드에서 부모 값입니다. 타이머 인터럽트가 발생할 때마다, `recent_cpu`는 실행 스레드만 실행되는 경우 1으로 증가합니다. 또한, 최근 cpu의 값은 이 공식을 사용하여 모든 스레드 (가동, 준비 또는 차단) 에 대해 초당 한 번 다시 계산됩니다.

> recent_cpu = (2 \* load_avg)/(2 \* load_avg + 1) \* recent_cpu + nice

여기서 `load_avg`은 실행할 준비가 된 스레드 수의 이동 평균입니다 (아래 참조). `load_avg`가 1, 평균적으로 하나의 스레드가 CPU를 위해 경쟁하고 있음을 나타내는 경우, 최근 CPU의 현재 값은 `.1`의 무게로 `log_(2/3) .1 ≈ 6` 초에 붕괴됩니다. 로드 avg가 2, `.1`의 무게로 붕괴는 `log_(3/4) .1 ≈ 8` 초에 소요됩니다. 효과는 최근 cpu가 CPU에 경쟁하는 스레드 수에 반사적으로 비례하는 붕괴율로 "최근"에 스레드가 받은 CPU 시간의 양을 추정한다는 것입니다.

일부 테스트는 recent cpu 재계산이 시스템 틱 카운터가 정확히 1초의 배수에 도달했을 때, 즉 `timer_ticks () % TIMER_FREQ == 0`일 때에만 수행된다고 가정합니다. 다른 시점에는 재계산하면 안 됩니다.

nice 값이 음수인 스레드는 `recent_cpu`도 음수일 수 있습니다. 음수인 `recent_cpu`를 0으로 제한하지 마세요.

이 식에서는 계산 순서를 고려해야 합니다. recent cpu의 계수를 먼저 계산한 뒤 곱하는 것을 권장합니다. `load_avg`와 `recent_cpu`를 바로 곱하면 오버플로가 발생할 수 있다는 보고가 있습니다.

`thread_get_recent_cpu()`을 구현해야 하는데, `threads/thread.c`에는 골격이 있습니다.

```
int thread_get_recent_cpu (void);
```

> 현재 스레드의 recent cpu 값에 100을 곱한 뒤 가장 가까운 정수로 반올림해 반환합니다.

<a id="calculating-loadavg"></a>

## `load_avg` 계산

load avg, 즉 시스템 부하 평균은 지난 1분 동안 실행 준비가 된 스레드 수의 평균을 추정합니다. `recent_cpu`처럼 지수 가중 이동 평균입니다. 우선순위나 `recent_cpu`와 달리 `load_avg`는 스레드별 값이 아닌 시스템 전체의 값입니다. 부팅 시 0으로 초기화하고 이후 1초마다 다음 식으로 갱신합니다.

> load_avg = (59/60) \* load_avg + (1/60) \* ready_threads,

ready threads는 갱신 시점에 실행 중이거나 실행 준비 상태인 스레드의 수입니다. 유휴 스레드는 제외합니다.

일부 테스트의 가정에 따라 `load_avg`는 시스템 틱 카운터가 정확히 1초의 배수에 도달한 시점, 즉 `timer_ticks () % TIMER_FREQ == 0`일 때에만 갱신해야 합니다. 다른 시점에 갱신하면 안 됩니다. `threads/thread.c`에 기본 틀이 있는 `thread_get_load_avg()`을 구현해야 합니다.

```
int thread_get_load_avg (void)
```

> 현재 시스템 부하 평균에 100을 곱한 뒤 가장 가까운 정수로 반올림해 반환합니다.

<a id="summary"></a>

## 요약

다음 공식은 스케줄러를 구현하기 위해 필요한 계산을 요약한다. 그들은 스케줄러 요구 사항에 대한 완전한 설명이 아닙니다.

각 스레드는 바로 통제하에 있는 -20에서 20 사이의 nice 값을 가지고 있습니다. 또한 각 스레드는 0 (`PRI_MIN`) 에서 63 (`PRI_MAX`) 까지의 우선순위를 가지고 있으며, 이 우선순위는 네 번째 틱마다 다음과 같은 공식을 사용하여 다시 계산됩니다.

> priority = PRI_MAX - (recent_cpu / 4) - (nice \* 2)

`recent_cpu`은 스레드가 최근 배정받은 CPU 시간을 측정합니다. 타이머 틱마다 현재 실행 스레드의 recent cpu를 1 증가시킵니다. 초당 한 번, 각 스레드의 최근 CPU는 다음과 같이 업데이트됩니다.

> recent_cpu = (2 \* load_avg) / (2 \* load_avg + 1) \* recent_cpu + nice

`load_avg`는 지난 분 동안 실행할 준비가 된 스레드 수 평균을 추정합니다. 시작 시 0으로 초기화되고 초당 한 번 다시 계산됩니다.

> load_avg = (59/60) \* load_avg + (1/60) \* ready_threads

`ready_threads`는 업데이트 시 실행 중인 또는 실행할 준비가 된 스레드 (무휴 스레드를 포함하지 않고) 의 수입니다.

<a id="fixed-point-real-arithmetic"></a>

## 고정소수점 실수 연산

위의 공식에서, `priority`, `nice` 및 `ready_threads`은 정수이지만, `recent_cpu` 및 `load_avg`은 실제 숫자입니다. 불행히도, Pintos는 커널에서 부동소수점 계산을 지원하지 않습니다, 왜냐하면 그것은 커널을 복잡하고 느리게 만들 것이기 때문입니다. 실제 커널은 같은 이유로 같은 한계를 가지고 있습니다. 이것은 실제 양에 대한 계산은 정수를 사용하여 시뮬레이션되어야 한다는 것을 의미합니다. 이것은 어렵지 않지만 많은 학생들이 어떻게 해야 하는지 모릅니다. 이 섹션 은 기본 을 설명 합니다.

근본적인 아이디어는 정수의 가장 오른쪽에 있는 부분을 분자를 나타내는 것으로 간주하는 것입니다. 예를 들어, 서명된 32비트 정수의 가장 낮은 14비트를 분자 비트로 지정할 수 있습니다. 그래서 정수 x는 실제 번호 `x/(2^14)`을 나타냅니다. 이것은 17.14의 고정소수점 숫자 표현이라고 불립니다. 왜냐하면 십자점 앞에 17 비트, 그 뒤에 14 비트, 그리고 하나의 신호 비트 있기 때문입니다. 17.14 형식의 숫자는 최대 `(2^31 − 1)/(2^14) ≈ 131,071.999`의 값을 나타냅니다.

`p.q` 고정소수점 형식을 사용하고 `f = 2^q`이라고 합시다. 위 정의에 따라 정수나 실수에 `f`를 곱하면 `p.q` 형식으로 바꿀 수 있습니다. 예를 들어 앞서 `load_avg` 계산에 사용한 분수 `59/60`은 17.14 형식에서 `(59/60)2^14 = 16,110`입니다. 고정소수점 값을 정수로 되돌리려면 `f`로 나눕니다. C의 일반 `/` 연산자는 0을 향해 절삭하므로 양수는 내리고 음수는 올립니다. 가장 가까운 정수로 반올림하려면 나누기 전에 양수에는 `f / 2`를 더하고 음수에서는 그만큼 빼세요.

고정소수점 숫자에 대한 많은 작업은 간단합니다. `x`과 `y`은 정점 숫자이고 `n`은 정수이다. 그러면 `x`와 `y`의 합은 `x + y`이고 그 차이가 `x - y`. `x`와 `n`의 합은 `x + n * f`; 차이, `x - n * f`; 제품, `x * n`; 양자, `x / n`.

고정소수점 값 두 개를 곱할 때에는 두 가지 문제가 있습니다. 첫째, 결과의 소수점이 왼쪽으로 q비트만큼 치우칩니다. `(59/60)(59/60)`은 `1`보다 조금 작아야 하지만 `16,111 × 16,111 = 259,564,321`는 `2^14 = 16,384`보다 훨씬 큽니다. 오른쪽으로 `q`비트 이동하면 `259,564,321/2^14 = 15,842`가 되어 올바른 값인 약 `0.97`을 얻습니다. 둘째, 최종 답을 표현할 수 있어도 중간 곱셈에서 오버플로가 발생할 수 있습니다. 예를 들어 17.14 형식에서 `64`는 `64 × 2^14 = 1,048,576`이고 그 제곱 `64^2 = 4,096`도 범위 안이지만, `1,048,576^2 = 2^40`는 부호 있는 32비트 정수의 최댓값 `2^31 − 1`보다 큽니다. 쉬운 해결책은 곱셈을 64비트로 수행하는 것입니다. 이때 x와 y의 곱은 `((int64_t) x) * y / f`입니다.

두 개의 고정소수점 값을 나누는 것은 반대되는 문제입니다. 열점은 오른쪽으로 너무 멀리 떨어져 있습니다. 우리는 이분하기 전에 이분 q 비트들을 왼쪽으로 이동시켜서 수정합니다. 왼쪽 전환은 배당의 상위 q 비트들을 버립니다. 64 비트로 나눌 때 다시 해결할 수 있습니다. 따라서, x가 y로 나눌 때 분수는 `((int64_t) x) * f / y`.

이 섹션에서는 두 가지 이유로 q-비트 전환이 아닌 `f`로 곱하거나 나누기를 일관되게 사용했습니다. 첫째, 곱셈과 분배는 C 시퀀스 운영자의 놀라운 운영자 우선순위를 가지고 있지 않습니다. 둘째, 곱셈과 분배는 부정적인 오페란드에서 잘 정의되어 있지만, C shift operators는 그렇지 않습니다. 이러한 문제들을 실행에 옮기는 데 주의를 기울여야 합니다.

다음 표는 C에서 고정 점 수학적 연산을 어떻게 구현할 수 있는지 요약합니다. 표에서, `x` 및 `y`은 고정소수점 번호, `n`은 정수, 고정소수점 번호는 서명된 `p.q` 형식으로 `p + q = 31`, 그리고 `f`는 `1 << q`:

| 수학자                                   | C                               |
|------------------------------------------|---------------------------------|
| `n`를 고정된 지점으로 변환               | `n * f`                         |
| `x`을 정수로 변환 (무로로 회전)          | `x / f`                         |
| `x`을 정수로 변환 (순형으로 가장 가까운) | `(x + f / 2) / f` 만약 `x >= 0` |
|                                          | `(x - f / 2) / f` 만약 `x <= 0` |
| `x`과 `y`를 추가합니다                   | `x + y`                         |
| `y`을 `x`에서 빼면                       | `x - y`                         |
| `x` 및 `n`을 추가                        | `x + n * f`                     |
| `n`에서 `x`을 빼면                       | `x - n * f`                     |
| `x`을 `y`로 곱하면                       | `((int64_t) x) * y / f`         |
| `x`을 `n`로 곱하면                       | `x * n`                         |
| `x`를 `y`로 나눈다                       | `((int64_t) x) * f / y`         |
| `x`를 `n`로 나눌 때                      | `x / n`                         |
