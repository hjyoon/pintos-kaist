# 우선순위 스케줄링

**Pintos에 우선순위 스케줄링과 우선순위 기부를 구현하세요.**

현재 실행 중인 스레드보다 우선순위가 높은 스레드가 준비 리스트에 추가되면, 현재 스레드는 즉시 새 스레드에 프로세서를 양보해야 합니다. 마찬가지로 락, 세마포어, 조건 변수를 기다리는 스레드 중에서는 우선순위가 가장 높은 스레드를 먼저 깨워야 합니다. 스레드는 언제든 자신의 우선순위를 높이거나 낮출 수 있습니다. 우선순위를 낮춰 더 이상 최고 우선순위가 아니게 되면 즉시 CPU를 양보해야 합니다.

스레드 우선순위의 범위는 `PRI_MIN (0)`부터 `PRI_MAX (63)`까지입니다. 숫자가 작을수록 우선순위가 낮으므로 0이 최저, 63이 최고입니다. 초기 우선순위는 `thread_create()`의 인자로 전달합니다. 다른 값을 선택할 이유가 없다면 `PRI_DEFAULT (31)`을 사용하세요. `PRI_` 매크로는 `threads/thread.h`에 정의돼 있으며 그 값을 변경하면 안 됩니다.

우선순위 스케줄링에는 '우선순위 역전' 문제가 있습니다. 우선순위가 높은 스레드 *H*, 중간인 *M*, 낮은 *L*을 생각해 봅시다. *H*가 *L*를 기다려야 하고, 예를 들어 *L*이 가진 락을 기다리는데 *M*이 준비 리스트에 있다면, 낮은 우선순위의 스레드가 CPU 시간을 얻지 못해 *H*도 CPU를 얻지 못합니다. 부분적인 해결책은 *L*이 락을 보유하는 동안 *H*가 자신의 우선순위를 *L*에 '기부'하는 것입니다. 이후 *L*이 락을 해제하고 *H*가 획득하면 그 기부를 회수합니다.

우선순위 기부를 구현하세요. 기부가 필요한 여러 상황을 모두 고려해야 합니다. 한 스레드에 여러 우선순위가 기부되는 다중 기부도 처리해야 합니다. 중첩 기부도 지원해야 합니다. *H*가 *M*의 락을 기다리고 *M*이 *L*의 락을 기다린다면 *M*과 *L* 모두 *H*의 우선순위로 올라가야 합니다. 필요하면 중첩 기부 깊이에 8단계 같은 합리적인 상한을 둘 수 있습니다.

락에 대해서는 우선순위 기부를 반드시 구현해야 합니다. 다른 Pintos 동기화 구성 요소에 기부를 구현할 필요는 없습니다. 다만 우선순위 스케줄링은 모든 경우에 구현해야 합니다.

마지막으로 스레드가 자신의 우선순위를 조회하고 변경하는 다음 함수들을 구현하세요. 함수의 기본 틀은 `threads/thread.c`에 있습니다.

------------------------------------------------------------------------

```
void thread_set_priority (int new_priority);
```

> 현재 스레드의 우선순위를 새 값으로 설정합니다. 더 이상 최고 우선순위가 아니면 CPU를 양보합니다.

------------------------------------------------------------------------

```
int thread_get_priority (void);
```

> 현재 스레드의 우선순위를 반환합니다. 우선순위를 기부받았다면 더 높은 기부 우선순위를 반환합니다.

한 스레드가 다른 스레드의 우선순위를 직접 변경하는 인터페이스를 제공할 필요는 없습니다.

이 우선순위 스케줄러는 후속 프로젝트에서 사용하지 않습니다.
