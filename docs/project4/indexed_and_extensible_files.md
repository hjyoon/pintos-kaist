# 인덱스 및 확장 가능한 파일

기본 파일 시스템은 파일을 하나의 연속 영역에 할당하므로 외부 단편화에 취약합니다. 빈 블록이 *n*개 있어도 연속 공간이 부족하면 *n*블록짜리 파일을 할당하지 못할 수 있습니다. 디스크에 저장되는 아이노드 구조를 수정해 이 문제를 해결하세요.

일반적으로는 직접·간접·이중 간접 블록을 갖는 인덱스 구조를 사용할 수 있습니다. 이전 학기에는 대부분 수업에서 배운 다단계 인덱싱 방식의 *버클리 UNIX FFS*와 비슷하게 구현했습니다. 이번에는 구현 부담을 줄이기 위해 더 단순한 FAT를 사용합니다. **제공된 스켈레톤 코드로 FAT를 구현해야 합니다.** 다단계 인덱싱, 즉 강의의 FFS를 구현하는 코드를 넣어서는 안 됩니다. 그런 경우 파일 확장 부분은 0점 처리됩니다.

참고: 파일 시스템 파티션은 8 MB 이하라고 가정할 수 있습니다. 메타데이터를 제외한 파티션 전체 크기만 한 파일을 지원해야 합니다. 각 아이노드는 한 디스크 섹터에 저장되므로 그 안에 넣을 수 있는 블록 포인터 수에 제한이 있습니다.

## FAT(File Allocation Table)를 이용한 대용량 파일 인덱싱

> 주의: 이 문서는 강의에서 일반적인 파일 시스템과 FAT의 기본 원리를 이미 이해했다고 가정합니다. 그렇지 않다면 강의 노트로 돌아가 파일 시스템과 FAT가 무엇인지 먼저 이해하세요.

이전 프로젝트의 기본 파일 시스템은 파일을 여러 디스크 섹터에 걸친 하나의 연속 영역에 저장했습니다. 하나 이상의 연속 섹터를 포함할 수 있는 *연속된 영역*을 *클러스터*라고 부릅시다. 이 관점에서 기존 파일 시스템의 클러스터 크기는 그 안에 저장된 파일 크기와 같았습니다.

외부 단편화를 줄이려면 가상 메모리의 페이지 크기를 떠올리며 클러스터 크기를 줄일 수 있습니다. 단순화를 위해 스켈레톤 코드에서는 클러스터당 섹터 수를 `1`로 고정합니다. 작은 클러스터 하나에 파일 전체를 저장할 수 없다면 여러 클러스터가 필요하므로 아이노드에서 이를 인덱싱할 자료 구조가 있어야 합니다. 가장 쉬운 방법 중 하나는 연결 리스트, 즉 *체인*입니다. 아이노드에 첫 블록의 섹터 번호를 저장하고 첫 블록에 두 번째 블록의 번호를 저장할 수 있습니다. 그러나 마지막 블록만 필요해도 앞선 모든 블록을 읽어야 하므로 이 방식은 느립니다. FAT(File Allocation Table)는 블록 사이의 연결 정보를 블록 자체 대신 고정 크기의 파일 할당 테이블에 저장합니다. 실제 데이터 대신 연결 정보만 담아 DRAM에 캐시할 수 있을 만큼 작습니다. 따라서 테이블의 해당 엔트리만 읽어 다음 블록을 찾을 수 있습니다.

`filesys/fat.c`의 스켈레톤 코드로 아이노드 인덱싱을 구현합니다. 아래에서는 `fat.c`에 이미 구현된 함수의 역할과 직접 구현할 함수를 간단히 설명합니다.

먼저 `fat.c`의 함수 6개, 즉 `fat_init()`, `fat_open()`, `fat_close()`, `fat_create()`, `fat_boot_create()`는 부팅 시 디스크를 초기화하고 포맷하므로 수정할 필요가 없습니다. 다만 `fat_fs_init()`는 직접 작성해야 합니다. 기존 함수의 역할도 간단히 이해해 두면 도움이 됩니다.

------------------------------------------------------------------------

```
cluster_t fat_fs_init (void);
```

> FAT 파일 시스템을 초기화합니다. `fat_fs`의 `fat_length`와 `data_start` 필드를 초기화해야 합니다. `fat_length`는 파일 시스템의 클러스터 수를, `data_start`는 파일 데이터를 저장하기 시작하는 섹터를 나타냅니다. `fat_fs->bs`에 저장된 값을 활용할 수 있습니다. 이 함수에서 다른 유용한 데이터도 초기화해도 됩니다.

------------------------------------------------------------------------

```
cluster_t fat_create_chain (cluster_t clst);
```

> 클러스터 번호 `clst`가 가리키는 클러스터 뒤에 새 클러스터를 붙여 체인을 늘립니다. `clst`가 0이면 새 체인을 만듭니다. 새로 할당한 클러스터 번호를 반환합니다.

------------------------------------------------------------------------

```
void fat_remove_chain (cluster_t clst, cluster_t pclst);
```

> `clst`에서 시작하는 클러스터들을 체인에서 제거합니다. `pclst`는 바로 앞 클러스터여야 하며, 실행이 끝나면 `pclst`가 남은 체인의 마지막 요소가 됩니다. `clst`가 체인의 첫 요소라면 `pclst`는 0이어야 합니다.

------------------------------------------------------------------------

```
void fat_put (cluster_t clst, cluster_t val);
```

> 클러스터 번호 `clst`에 해당하는 FAT 엔트리를 `val`로 갱신합니다. FAT 엔트리는 다음 클러스터를 가리키며, 다음 클러스터가 없으면 `EOChain`입니다. 따라서 체인의 연결 관계를 갱신하는 데 사용할 수 있습니다.

------------------------------------------------------------------------

```
cluster_t fat_get (cluster_t clst);
```

> 주어진 클러스터 `clst`가 가리키는 다음 클러스터의 번호를 반환합니다.

------------------------------------------------------------------------

```
disk_sector_t cluster_to_sector (cluster_t clst);
```

> 클러스터 번호 `clst`를 대응하는 디스크 섹터 번호로 변환해 반환합니다.

------------------------------------------------------------------------

이 함수들을 `filesys.c`와 `inode.c`에서 사용해 기본 파일 시스템을 확장할 수 있습니다.

## 파일 확장

**확장 가능한 파일을 구현하세요.** 기본 파일 시스템은 생성할 때 파일 크기를 지정합니다. 반면 대부분의 현대 파일 시스템은 크기 0으로 파일을 만든 뒤 파일 끝을 넘겨 쓸 때마다 크기를 늘립니다. 여러분의 파일 시스템도 이를 지원해야 합니다.

메타데이터를 제외한 파일 시스템 크기를 넘을 수 없다는 것 외에는 파일 크기에 미리 정한 상한을 두면 안 됩니다. 루트 디렉터리 파일도 마찬가지이며, 기존의 파일 16개 제한을 넘어 커질 수 있어야 합니다.

유저 프로그램은 현재 파일 끝(EOF)을 넘는 위치로 seek할 수 있습니다. seek 자체는 파일을 확장하지 않습니다. EOF 이후에 쓰면 해당 위치까지 파일을 확장하고 이전 EOF와 쓰기 시작점 사이를 0으로 채워야 합니다. EOF를 넘는 위치에서 읽기 시작하면 읽은 바이트 수는 0입니다.

EOF에서 멀리 떨어진 곳에 쓰면 여러 블록이 전부 0으로 채워질 수 있습니다. 어떤 파일 시스템은 이러한 블록에도 실제 데이터 블록을 할당하고 0을 씁니다. 다른 파일 시스템은 그 블록에 명시적인 쓰기가 발생하기 전에는 할당하지 않습니다. 후자는 희소 파일(sparse file)을 지원한다고 합니다. 두 할당 전략 중 어느 쪽을 선택해도 됩니다.
