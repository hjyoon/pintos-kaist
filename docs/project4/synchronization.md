# 동기화

제공된 파일 시스템에는 외부 동기화가 필요합니다. 즉, 호출자는 파일 시스템 코드에서 한 번에 하나의 스레드가 실행될 수 있는지 확인해야합니다. 귀하의 제출은 외부 동기화를 필요로 하지 않는 더 정밀한 동기화 전략을 채택해야 합니다. 가능한 한 독립된 단체를 대상으로 하는 사업은 독립적이어야 하며, 서로 기다리지 않아도 된다.

다른 캐시 블록의 동작은 독립적이어야 합니다. 특히 특정 블록에서 I/O가 요구되는 경우, I/O가 완료될 때까지 기다리지 않고 I/O가 필요하지 않은 다른 블록에 대한 작업이 진행되어야 합니다.

여러 프로세스가 한 번에 하나의 파일에 접근 할 수 있어야 합니다. 하나의 파일의 여러 개의 읽기가 서로 기다리지 않고 완료될 수 있어야 합니다. 파일에 작성하면 파일이 확장되지 않을 때, 여러 프로세스는 동시에 하나의 파일을 작성할 수 있어야 합니다. 한 프로세스에 의해 파일의 읽기, 다른 프로세스에 의해 파일이 작성되는 경우 기록의 어느 것도, 전부 또는 일부가 완료되지 않았음을 보여줄 수 있습니다. (그러나 `write` 시스템 호출이 호출자에게 돌아온 후, 모든 후속 독자는 변경 사항을 볼 수 있습니다.) 마찬가지로, 두 프로세스가 파일의 동일한 부분에 동시에 작성할 때, 그들의 데이터가 얽혀있을 수 있습니다.

다른 한편으로, 새로운 섹션에 파일을 확장하고 데이터를 작성하는 것은 원자적이어야합니다. A과 B 프로세스는 모두 주어진 파일을 열고 모두 파일 끝에 위치하고 있다고 가정합니다. A가 동시에 파일을 읽고 B가 작성한다면 A는 B가 작성한 모든 것을, 일부 또는 아무것도 읽을 수 있습니다. 그러나 A는 B가 작성하는 것 이외의 데이터를 읽지 않을 수 있습니다. 예를 들어 B의 데이터는 모두 비 0 바이트라면 A는 어떤 0도 볼 수 없습니다.

다른 디렉토리에서의 작업은 동시에 이루어져야 한다. 같은 디렉토리에 있는 작업들은 서로 기다리고 있을 수 있습니다.

여러 개의 스레드에서 공유되는 데이터만 동기화되어야한다는 것을 명심하십시오. 기본 파일 시스템에서, `struct file` 및 `struct dir`은 하나의 스레드에서만 접근 할 수 있습니다.
