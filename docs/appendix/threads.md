# 스레드

<a id="struct-thread"></a>

## `struct thread`

노선에 대한 Pintos의 주요 데이터 구조는 `struct thread`, `threads/thread.h`에 명시되어 있습니다.

------------------------------------------------------------------------

```
struct thread;
```

스레드 또는 사용자 프로세스를 나타냅니다. 프로젝트에서는 자신의 회원을 `struct thread`에 추가해야 합니다. 또한 기존 회원의 정의를 변경하거나 삭제할 수 있습니다. 각 `struct thread`은 자신의 메모리 페이지의 시작을 차지합니다. 페이지의 나머지 부분은 페이지의 끝에서 아래로 성장하는 스틱을 위해 사용됩니다. 이렇게 생겼습니다.

                          4 kB +---------------------------------+
                               |         kernel stack            |
                               |               |                 |
                               |               |                 |
                               |               V                 |
                               |        grows downward           |
                               |                                 |
                               |                                 |
                               |                                 |
                               |                                 |
                               |                                 |
                               |                                 |
                               |                                 |
                               |                                 |
        sizeof (struct thread) +---------------------------------+
                               |             magic               |
                               |          intr_frame             |
                               |               :                 |
                               |               :                 |
                               |             status              |
                               |              tid                |
                          0 kB +---------------------------------+

이것은 두 가지 결과를 낳습니다. 첫째, `struct thread`은 너무 커질 수 없습니다. 그렇게 되면 커널 스택에 충분한 공간이 없을 것입니다. 기본 `struct thread`의 크기는 몇 바이트밖에 되지 않습니다. 아마도 1kB 이하로 남아있을 것입니다. 둘째, 커널 스택이 너무 큰 것을 허용해서는 안 됩니다. 스택이 지나가면 스레드 상태가 손상됩니다. 따라서 커널 함수는 큰 구조나 배열을 비정형 로컬 변수로 할당해서는 안 됩니다. 대신 `malloc()` 또는 `palloc_get_page()` ([메모리 분배](memory_allocation.md) 참조) 와 함께 동적 할당을 사용하십시오.

------------------------------------------------------------------------

```
tid_t tid;
```

> 스레드의 스레드 식별자 또는 tid. 각 스레드는 커널의 평생 동안 고유한 타이드를 가져야 합니다. 기본적으로 `tid_t`은 `int`에 대한 `typedef`이며, 각 새로운 스레드는 초기 프로세스에 대해 1에서 시작하여 숫자적으로 다음 더 높은 스레드를 받는다. 원하는 경우 타입과 번호를 변경할 수 있습니다.

------------------------------------------------------------------------

```
enum thread_status status;
```

> 나선 상태, 다음 중 하나:
>
> - `THREAD_RUNNING`
>
>   스레드가 실행 중입니다. 어떤 시점이든 정확히 하나의 스레드가 실행됩니다. `thread_current()`는 그 스레드를 반환합니다.
>
> - `THREAD_READY`
>
>   스레드 가동이 준비됐지만 지금은 가동이 되지 않습니다. 스레드는 다음 번에 스케줄러를 호출할 때 실행되도록 선택될 수 있습니다. 준비된 스레드는 `ready_list`라는 두 배로 연결된 목록에 보관됩니다.
>
> - `THREAD_BLOCKED`
>
>   락을 사용할 수 있게 되거나 인터럽트가 발생하는 등의 사건을 기다리는 상태입니다. `thread_unblock()`를 호출해 `THREAD_READY` 상태로 전환하기 전에는 다시 스케줄되지 않습니다. 보통 스레드를 자동으로 블록·해제하는 Pintos 동기화 기본 요소를 이용해 간접적으로 처리하는 것이 가장 편리합니다. [동기화](synchronization.md)를 참고하세요. 블록된 스레드가 무엇을 기다리는지 알려 주는 *우선적으로* 방법은 없지만, 백트레이스가 도움이 될 수 있습니다. [후퇴](threads.md)을 참고하세요.
>
> - `THREAD_DYING`
>
>   다음 스레드로 전환한 뒤 스케줄러가 이 스레드를 해제합니다.

------------------------------------------------------------------------

```
char name[16];
```

> 끈의 이름은 문자열, 또는 적어도 그 첫 글자 몇 개.

------------------------------------------------------------------------

```
struct intr_frame tf;
```

> 레지스터와 스택 포인터를 포함하는 컨텍스트 전환을 위한 정보를 저장합니다.

------------------------------------------------------------------------

```
int priority;
```

> `PRI_MIN` (0)에서 `PRI_MAX` (63) 까지의 스레드 우선순위 낮은 숫자는 낮은 우선순위에 해당하므로 우선순위는 0이고 우선순위는 63입니다. 제공된 Pintos는 스레드 우선순위를 무시하지만 프로젝트 1에서 우선순위 스케줄을 구현할 것입니다 ([우선순위 기획](../project1/priority_scheduling.md) 참조).

------------------------------------------------------------------------

```
struct list_elem elem;
```

> 스레드를 이중 연결된 리스트에 넣기 위해 사용되는 " 리스트 요소", 또는 `ready_list` (운동할 준비가 된 스레드 목록) 또는 `sema_down()`에서 세마포어를 기다리는 스레드 목록. 이중 직무를 수행할 수 있습니다. 왜냐하면 신호등에 기다리는 끈이 준비되지 않았기 때문입니다. 그리고 반대로요.

------------------------------------------------------------------------

```
uint64_t *pml4;
```

> 단지 프로젝트 2 및 후기에서만 존재합니다. [페이지 테이블](virtual_address.md) 참조

------------------------------------------------------------------------

```
unsigned magic
```

> 항상 `THREAD_MAGIC`로 설정합니다. 이 값은 `threads/thread.c`에 정의된 임의의 숫자로 스택 오버플로를 감지하는 데 사용합니다. `thread_current()`는 실행 중인 스레드의 `struct thread` 안에 있는 `magic` 멤버가 `THREAD_MAGIC`인지 검사합니다. 스택 오버플로는 대개 이 값을 바꿔 단언 실패를 일으킵니다. 이 검사의 효과를 유지하려면 `struct thread`에 멤버를 추가할 때 `magic`를 마지막에 두세요.

<a id="thread-functions"></a>

## 스레드 함수

`threads/thread.c`는 스레드 지원에 대한 여러 공공 함수를 구현합니다. 가장 유용한 것을 살펴보자.

------------------------------------------------------------------------

```
void thread_init (void);
```

> 스레드 시스템을 초기화하기 위해 `main()`에서 호출합니다. 주된 목적은 Pintos 최초 스레드의 `struct thread`를 만드는 것입니다. 로더가 최초 스레드의 스택도 다른 스레드와 같은 페이지 상단 위치에 배치하므로 가능합니다.
>
> `thread_init()`가 실행되기 전에, `thread_current()`는 실행 스레드의 `magic` 값이 잘못되었기 때문에 실패합니다. 많은 함수는 `thread_current()`을 직접 또는 간접적으로 호출합니다. 잠금을 잠금하기 위해 `lock_acquire()`를 포함하여, 그래서 `thread_init()`은 Pintos 초기화 초기에서 호출됩니다.

------------------------------------------------------------------------

```
void thread_start (void);
```

> 스케줄러를 시작하기 위해 `main()`에서 호출합니다. 준비된 다른 스레드가 없을 때 실행할 유휴 스레드를 만듭니다. 이어서 인터럽트를 활성화합니다. 타이머 인터럽트에서 반환할 때 `intr_yield_on_return()`를 이용해 스케줄러가 실행되므로, 결과적으로 스케줄링도 활성화됩니다.

------------------------------------------------------------------------

```
void thread_tick (void);
```

> 타이머 틱마다 타이머 인터럽트가 호출합니다. 스레드 통계를 추적하고 시간표가 만료되면 스케줄러를 실행합니다.

------------------------------------------------------------------------

```
void thread_print_stats (void);
```

> Pintos 종료 기간 동안 스레드 통계를 인쇄하기 위해 호출했습니다.

------------------------------------------------------------------------

```
tid_t thread_create (const char *name, int priority, thread func *func, void *aux);
```

> 주어진 priority와 이름 name으로 스레드를 생성·시작하고 새 스레드의 tid를 반환합니다. 스레드는 aux를 유일한 인자로 전달해 func를 실행합니다.
>
> `thread_create()`는 스레드의 `struct thread`와 스택을 위한 페이지를 할당하고 멤버를 초기화한 뒤 초기 실행을 위한 가짜 스택 프레임들을 구성합니다. 스레드는 처음에는 블록 상태이며 반환 직전에 블록을 해제해 스케줄될 수 있게 합니다.

------------------------------------------------------------------------

```
void thread_func (void *aux);
```

> 이 함수는 `thread_create()`에 전달되는 함수의 유형입니다. 이 함수의 추론으로 aux 추론이 전달됩니다.

------------------------------------------------------------------------

```
void thread_block (void);
```

> 실행 상태에서 차단 상태로 실행 스레드를 전환합니다. `thread_unblock()`가 호출될 때까지 이 스레드가 다시 실행되지 않을 것입니다. 그래서 그런 일이 일어나기 위해 어떤 방법을 마련하는 것이 좋습니다. `thread_block()`은 매우 낮은 수준이기 때문에 동기화 원시 중 하나를 사용하는 것이 좋습니다 ([동기화](synchronization.md) 참조).

------------------------------------------------------------------------

```
void thread_unblock (struct thread *thread);
```

> 차단된 상태에서 준비된 상태로 전환 스레드, 다시 실행할 수 있도록 합니다. 이것은 스레드가 기다리고 있는 이벤트가 발생했을 때 호출됩니다. 예를 들어 스레드가 기다리고 있는 잠금이 사용할 수있을 때.

------------------------------------------------------------------------

```
struct thread *thread_current (void);
```

> 실행 중인 스레드를 반환합니다.

------------------------------------------------------------------------

```
tid_t thread_tid (void);
```

> 실행 스레드의 스레드 ID를 반환합니다. `thread_current ()->tid`과 동등합니다.

------------------------------------------------------------------------

```
const char *thread_name (void);
```

> 실행 스레드의 이름을 반환합니다. `thread_current ()->name`과 동등합니다.

------------------------------------------------------------------------

```
void thread_exit (void) NO_RETURN;
```

> 현재 스레드를 종료합니다. 반환하지 않습니다.

------------------------------------------------------------------------

```
void thread_yield (void);
```

> CPU를 스케줄러에 양보해 다음 실행 스레드를 선택하게 합니다. 다시 현재 스레드가 선택될 수도 있으므로 일정 시간 동안 현재 스레드가 실행되지 않는다고 가정하면 안 됩니다.

------------------------------------------------------------------------

```
int thread_get_priority (void);
void thread_set_priority (int new_priority);
```

> 스터브를 설정하고 스레드 우선순위를 얻으십시오. [우선순위 기획](../project1/priority_scheduling.md) 참조

------------------------------------------------------------------------

```
int thread_get_nice (void);
void thread_set_nice (int new_nice);
int thread_get_recent_cpu (void);
int thread_get_load_avg (void);
```

> 선진 스케줄러를 위한 물건.
