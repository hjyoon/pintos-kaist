# 채점

과제는 테스트 결과를 기준으로 채점합니다.

<a id="testing"></a>

## 테스트

테스트 점수는 제공된 테스트의 결과로 결정합니다. 프로젝트마다 `tests`로 시작하는 이름의 테스트가 여러 개 있습니다. 전체 제출물을 테스트하려면 프로젝트의 `build` 디렉터리에서 make check를 실행하세요. 각 테스트를 빌드하고 실행한 뒤 `pass` 또는 `fail`를 출력합니다. 실패하면 원인에 대한 세부 정보도 출력하며, 모두 실행한 뒤에는 요약을 보여 줍니다. 개별 테스트를 실행할 수도 있습니다. 테스트 `t`는 출력을 `t.output`에 기록하고, 스크립트가 이를 `pass` 또는 `fail`로 판정해 `t.result`에 씁니다. 하나만 실행하고 채점하려면 `build`에서 `.result` 파일을 명시적으로 만드세요. 예를 들면 `make tests/threads/alarm-multiple.result`입니다. make가 최신 결과라고 판단하지만 다시 실행하고 싶다면 make clean을 실행하거나 `.output` 파일을 직접 삭제하세요. 기본적으로 테스트 실행 도중에는 피드백을 주지 않고 완료 후에만 결과를 보여 줍니다. 실행 과정을 보고 싶다면 make 명령행에 `VERBOSE=1`를 지정하세요. 예를 들면 make check `VERBOSE=1`입니다. 모든 테스트와 관련 파일은 `pintos/src/tests`에 있습니다. 올바른 테스트를 사용하도록 제출물을 채점하기 전에 이 디렉터리를 수정하지 않은 원본으로 교체합니다. 디버깅을 위해 테스트를 수정해도 되지만 실제로 실행하는 것은 원본입니다. 모든 소프트웨어에 버그가 있듯 테스트에도 결함이 있을 수 있습니다. 실패 원인이 자신의 코드가 아니라 테스트의 버그라고 생각하면 알려 주세요. 검토하고 필요하면 수정하겠습니다. 테스트를 공개한 점을 악용해서는 안 됩니다. 제공된 사례뿐 아니라 일반적인 경우에도 코드가 올바르게 동작해야 합니다. 예를 들어 실행 중인 테스트 이름에 따라 커널 동작을 명시적으로 바꾸는 것은 허용되지 않습니다. 테스트를 우회하려는 시도에는 점수를 주지 않습니다. 자신의 구현이 모호한 경우에 해당할 것 같다면 문의하세요.

<a id="submission"></a>

## 제출

제출용 압축 파일을 만드는 명령을 제공합니다. `threads`, `userprog`, `vm`, `filesys` 디렉터리가 있는 Pintos 프로젝트 루트로 이동하세요. `TEAM=YOUR_TEAM_NUMBER make archive`를 실행합니다. 예를 들면 `TEAM=5 make archive`입니다. 같은 디렉터리에 `team5.tar.gz`이 생성되면 그 파일을 제출하세요. 중복 제출은 **금지**입니다. 팀당 한 번만 제출하면 됩니다.
