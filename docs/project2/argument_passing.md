# 인자 전달

**`process_exec()`에서 사용자 프로그램에 대한 인자을 설정**

<a id="x86-64-calling-convention"></a>

## x86-64 호출 규약

이 섹션에서는 64 비트 x86-64 UNIX 구현에서 정상적인 함수 호출에 사용되는 컨벤션의 중요한 점을 요약합니다. 몇 가지 세부 사항은 간략하기 위해 생략되었습니다. 자세한 내용은 [시스템 V AMD64 ABI](https://en.wikipedia.org/wiki/X86_calling_conventions#System_V_AMD64_ABI)을 참조하십시오.

호출 규약은 다음과 같습니다.

1.  사용자 수준의 응용 프로그램은 `%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8` 및 `%r9` 순서를 통과하기 위해 정수 레지스터로 사용합니다.
2.  호출자는 다음 명령의 주소를 (회환 주소를) 스택에 밀어 넣고 호출자의 첫 번째 명령으로 뛰어납니다. 하나의 x86-64 명령어인 `CALL`은 둘 다 수행합니다.
3.  칼리는 처형한다.
4.  만약 Callee가 반환값을 가지고 있다면, 그것은 레지스터 RAX에 저장합니다.
5.  호출자는 복귀 주소를 스택에서 팝업하고 x86-64 `RET` 명령어를 사용하여 지정된 위치로 건너가 반환합니다.

3 int 인자을 필요로 하는 함수인 `f()`을 생각해 봅시다. 이 다이어그램은 표본 스택 프레임과 위의 단계 3의 시작에서 호출자가 보았던 레지스터 상태를 보여줍니다. `f()`는 `f(1, 2, 3)`로 호출되는 것을 가정합니다. 초기 스택 주소는 임의입니다:

                                 +----------------+
    stack pointer --> 0x4747fe70 | return address |
                                 +----------------+
    RDI: 0x0000000000000001 | RSI: 0x0000000000000002 | RDX: 0x0000000000000003

## 프로그램 시작 시의 세부 사항

유저 프로그램용 Pintos C 라이브러리는 `lib/user/entry.c`의 `_start()`를 유저 프로그램 진입점으로 사용합니다. 이 함수는 `main()`를 감싼 래퍼로, `main()`에서 반환하면 `exit()`를 호출합니다.

```
void
_start (int argc, char *argv[]) {
    exit (main (argc, argv));
}
```

커널은 사용자 프로그램이 실행을 시작하기 전에 초기 함수에 대한 인자을 레지스터에 넣어야 합니다. 논쟁은 일반적인 호출 협약과 같은 방식으로 전달됩니다.

다음 예제 명령어: `/bin/ls -l foo bar`에 대한 논쟁을 처리하는 방법을 고려하십시오.

1.  명령어를 단어로 나눌 때: `/bin/ls`, `-l`, `foo`, `bar`.

2.  단어들을 스택의 꼭대기에 올려주세요. 질서가 중요하지 않습니다. 왜냐하면 그들은 포인터를 통해 참조될 것이기 때문입니다.

3.  각 문자열의 주소를 누르며 0의 포인터 센티널을 눌러 오른쪽에서 왼쪽으로 이것은 argv의 요소입니다. nullpointer sentinel는 C 표준에 따라 `argv[argc]`이 nullpointer라는 것을 보장합니다. 명령은 `argv[0]`이 가장 낮은 가상 주소에 있다는 것을 보장합니다. 워드 어라인드 접근는 어라인드 접근보다 더 빠르기 때문에, 가장 좋은 성능을 위해, 스택 포인터를 8번의 복수까지 돌립니다.

4.  `%rsi`을 `argv` (`argv[0]`) 로 표시하고 `%rdi`을 `argc`로 설정합니다.

5.  마지막으로 가짜 "귀환 주소"를 누르십시오. 입력 함수는 결코 돌아오지 않지만, 그 스택 프레임은 다른 모든 것과 동일한 구조를 가져야 합니다.

아래 표는 사용자 프로그램 시작 직전에 스택과 관련 레지스터의 상태를 보여줍니다. 스택이 낮아지는 것을 참고하십시오.

| 주소       | 이름             | 데이터      | 유형         |
|------------|------------------|-------------|--------------|
| 0x4747fffc | argv\[3\]\[...\] | 'bar\0'     | char\[4\]    |
| 0x4747fff8 | argv\[2\]\[...\] | 'foo\0'     | char\[4\]    |
| 0x4747fff5 | argv\[1\]\[...\] | '-l\0'      | char\[3\]    |
| 0x4747ffed | argv\[0\]\[...\] | '/bin/ls\0' | char\[8\]    |
| 0x4747ffe8 | 단어 연계        | 0           | uint8_t\[\]  |
| 0x4747ffe0 | argv\[4\]        | 0           | char \*      |
| 0x4747ffd8 | argv\[3\]        | 0x4747fffc  | char \*      |
| 0x4747ffd0 | argv\[2\]        | 0x4747fff8  | char \*      |
| 0x4747ffc8 | argv\[1\]        | 0x4747fff5  | char \*      |
| 0x4747ffc0 | argv\[0\]        | 0x4747ffed  | char \*      |
| 0x4747ffb8 | 반환 주소        | 0           | void (\*) () |

> RDI: 4 RSI: 0x4747ffc0

이 예제에서는 스택 포인터를 `0x4747ffb8`로 초기화합니다. 위 설명처럼 `include/threads/vaddr.h`에 정의된 `USER_STACK`에서 스택을 시작하도록 작성해야 합니다.

`<stdio.h>`에서 선언된 비표준 `hex_dump()` 함수는 논증 통과 코드를 디버깅하는 데 유용하게 사용될 수 있습니다.

## 인자 전달 구현

현재 `process_exec()`는 새로운 프로세스에 대한 인자을 전달하는 것을 지원하지 않습니다. 이 기능을 실행하여 `process_exec()`을 확장하여 단순히 프로그램 파일 이름을 논증으로 받아들이는 대신 공간에 있는 단어로 나눕니다. 첫 번째 단어는 프로그램 이름이고, 두 번째 단어는 첫 번째 논쟁입니다. 즉, `process_exec("grep foo bar")`은 두 개의 논증 foo와 bar을 통과하여 grep를 실행해야 합니다.

명령 줄 내에서 여러 공간은 하나의 공간과 동등하므로 `process_exec("grep foo bar")`은 우리의 원본 사례와 동등합니다. 명령 줄 논증의 길이를 합리적으로 제한할 수 있습니다. 예를 들어, 하나의 페이지 (4kB) 에 들어갈 수 있는 논의를 제한할 수 있습니다. (Pintos 유틸리티가 커널에 전달할 수 있는 명령 줄 논증에 128 바이트의 무관한 제한이 있습니다.)

인자 문자열은 원하는 방식으로 분석해도 됩니다. 방법이 떠오르지 않으면 `strtok_r()`를 살펴보세요. 원형은 `include/lib/string.h`에 있고 `lib/string.c`에 자세한 주석과 함께 구현돼 있습니다. 프롬프트에서 `man strtok_r`를 실행해 man 페이지를 읽으면 더 자세히 알 수 있습니다.
